# Slice 02 - LLM / natural-language explanations of ML predictions (soccer + general ML): is faithfulness evaluated?

Compiled 2026-09-27. Labels: **FACT** (checked in a primary source I read), **AUTHOR CLAIM** (what the paper says about itself; I did not re-verify it), **SYNTHESIS** (my inference from several sources), **SPECULATION** (a guess). Evidence levels: FULL TEXT (I read the PDF text, or at least the relevant sections), ABSTRACT (arXiv or publisher abstract only), SECONDHAND (reported by another paper or a search snippet).

Settings used throughout:
- **(a) Verbalize provided attributions**: model -> SHAP or contributions -> LLM -> text. Faithfulness here means faithful *to the attribution table*. If the attribution is exact, that also means faithful to the model; for logistic regression contributions it is exact.
- **(b) LLM explains a black box from inputs and outputs only**: the LLM is used as a post hoc explainer, e.g. via in-context learning (ICL).
- **(c) LLM is the predictor and explains itself**: self-explanation, chain-of-thought (CoT).

## 2. Deep notes

### 2.1 Rahimian, Flisar, Sumpter (2025): wordalisation of an xG model (FULL TEXT + code)

**Citation (FACT):** Pegah Rahimian (Uppsala), Jernej Flisar (Twelve Football), David Sumpter (Uppsala / Twelve). "Automated explanation of machine learning models of footballing actions in words." *Journal of Sports Analytics* 11, July 2025, doi:10.1177/22150218251353089 (Crossref). Preprint: arXiv:2504.00767 (1 Apr 2025). The journal abstract is essentially the same as the arXiv one. From the abstract alone, I found no sign that a human evaluation was added in the journal version. That is unverified, because SAGE blocked the full text (HTTP 403).

**What "wordalisation" means (FACT, from Caut et al. and Rahimian et al.):** the word is a play on "visualisation". An LLM turns numbers into "concise, easily digestible narratives that summarize data-driven observations without directly reporting numerical values." The key design choice is that **the numbers-to-words mapping is done deterministically *before* the LLM**, producing a "synthesized text". The LLM then only restyles that text.

**Pipeline (FACT):**
1. *Model.* One logistic regression xG model per competition. Features: squared distance to centre, distance to goal, nearby opponents within 3 m, opponents in the shooting triangle, GK distance to goal, distance to nearest opponent, angle to GK, left foot, after throw-in, corner, or free kick. Features were selected on EURO 2024 by correlation and p-values. Some were kept "for interpretability" even when non-significant.
2. *Contribution.* c_j = beta_j * (x_j - mean_j) in log-odds. This is exactly the linear-SHAP value for a linear model with independent features, so the explanation is exact for the model. It is measured relative to the *average shot in that competition*.
3. *"Tell it what data to use."* xG is mapped to 5 percentile bins ("slim" ... "excellent chance"). Continuous features are mapped to percentile words ("close-range", "tight angle"). Binary features use fixed sentences. Contributions are ranked by |c_j|, and **only features with |c_j| > 0.1 log-odds are verbalized**, using the template "*The most impactful feature is X, which had the positive contribution because <absolute-value description>. This feature increased the xG*" (code: `utils/sentences.py::describe_shot_contributions`).
4. *LLM stage.* System prompt ("who it is"). 43 Q/A pairs ("what it knows"). 3 hand-written few-shot examples ("how to answer"). The LLM produces a short, engaging commentary.

**Evaluation (FACT):** five conditions. Case 1: description + features only. Case 2: + contributions (no LLM restyling). Case 3: wordalisation without the Q/A and few-shot steps. Case 4: full wordalisation. Case 5: raw numbers. Engagement: the LLM rates "how interesting" from 0-5. Accuracy: the LLM is asked "was [Feature] a positive, negative, or not contributing factor?" and the answer is compared with the +/-0.1 threshold truth. **Accuracy was computed only for Euclidean distance to goal and vertical distance to centre.** Scores were averaged over 10 runs. The code (`pages/eval.py`) shows the judge is Gemini with `temperature=1`, the same family that generates the text.

**Critical observations:**
- (SYNTHESIS) **The accuracy test is weak.** It uses the two most dominant, most intuitive features, exactly where LLM priors and the model agree. There is no test of "not contributing" features that an LLM might still talk up (e.g. "defensive pressure"), no count of features mentioned that are not in the model, and no rank or magnitude check. The same model family judges its own output, and no judge validation like #4's is reported.
- (FACT, from Fig. 5a of the paper) **The deterministic template layer itself produces confusing sentences**, because contributions are *mean-centred* while the "because" clause describes the *absolute* value. Example: "*number of opponents in triangle ... had the maximum positive contribution because the shot was heavily contested, with multiple opponents blocking the path*". Another: "*shot taken with left foot, which had the maximum positive contribution because the shot was with the right foot.*" Both may be faithful to the model: a right-footed shot where left-footed shots have a negative beta; or fewer opponents than the competition average. But they read as contradictions and invite an LLM to "fix" them using football priors. (SYNTHESIS) This is a natural, non-synthetic source of prior-vs-model conflict of the kind #4 only created artificially.
- (FACT) The authors say they have not done SHAP on non-linear models ("an interesting and open research challenge") and have not done human evaluation with coaches ("the focus of the next steps").
- (FACT) Code: `Peggy4444/shotsGPT` (GPL-3.0, 15 stars, last push Nov 2025). It includes per-competition model parameters and the `Case1-4.csv` evaluation outputs, and uses StatsBomb open data (free). The LLM backend is Azure OpenAI through `openai==0.28` or Gemini. Q/A retrieval uses embeddings (ada or Gemini).

**Citing papers (FACT, S2 + OpenAlex, 2026-09-27):** there are very few citations: a Slovenian systematic review, an evaluation of FIFA Football AI Pro, and a general LLM survey (Electronics 2025). **None of them evaluates wordalisation faithfulness.** Related Sumpter-group work: Caut et al. 2025/26 (#2) and Prompt Cards 2026 (#3). Blog posts: "Introducing Wordalisations" and "Context engineering for building football AI" (soccermatics.medium.com).

### 2.2 Ichmoukhamedov, Hinns, Martens (2024): *How good is my story?* (FULL TEXT). **The closest prior work, and it partly falsifies the soccer "domain-prior" gap.**
- (FACT) Setting (a). RF + TreeSHAP. The top 4 features (name, SHAP value, feature value, feature average, description) are passed to the generator.
- (FACT) **Extraction-based faithfulness**: a second LLM returns `{feature: {rank, sign, value, assumption}}`. RA/SA/VA are simple accuracies against the SHAP table. Extracted features that are not in the table are *omitted* from scoring, so hallucinated features are not scored. The extractor was validated with 60 permuted narratives (all flagged) and 60 human narratives (1 false negative).
- (FACT) **"Assumptions" = domain knowledge the LLM injects** to justify a feature ("aggressive play is generally not appreciated in football"). This is scored with perplexity under Llama-3-8B / Mistral-7B. Perplexity works on isolated sentences but was **inconclusive** inside real narratives.
- (FACT) **Manipulation experiment**: the SHAP table's rank order is inverted and signs are flipped. SA against the *original* table (i.e. the LLM "self-corrected" the sign) was 0.15-0.31 pooled over the 3 datasets, depending on the model (Table III), and 0.14-0.38 on the FIFA MoM dataset alone (Table IV). About 0.04 was expected. Their example: the LLM refuses to say "scoring five goals reduces the team's probability of winning Man of the Match". A feature-level analysis on Student data shows the corrections go in the "intuitive" direction ("going out is bad for grades"). The authors call this a hallucination similar to parametric-knowledge bias.
- (FACT) Datasets include **FIFA Man of the Match** (team-level match stats, Kaggle). So a *soccer-flavoured* tabular dataset has already been used.
- (SYNTHESIS) What it does **not** do: natural (non-manipulated) conflicts; models with correlated or collinear features where SHAP is counter-intuitive but correct; event/tracking-level soccer models (xG/xT/VAEP); features that are *absent* from the model but salient in the domain; small local LLMs as the generator; any visual interface; any human study.

### 2.3 Explingo (Zytek et al., IEEE BigData 2024) (FULL TEXT)
- (FACT) Accuracy (binary) and completeness (0/1/2) are graded by GPT-4o, with the prompt iterated until it reached 96% agreement with 50 human-labelled pairs per metric.
- (FACT) **Few-shot exemplars trade correctness for style.** Zero-shot accuracy is 4.0/4. With 1-5 hand-written exemplars it falls to about 3.1-3.3 ("more exemplars ... may increase the chance of the NARRATOR hallucinating"). This parallels Rahimian's engagement/accuracy trade-off.
- (FACT) Mistral-7B as narrator matched style (fluency 3.91) but **accuracy 0.98/4 and completeness 1.64/4**, because it "did not always parse the input explanation correctly". This is direct evidence that small local models are the weak point.
- (FACT) Domain effect: on the mushroom dataset the grader marked a correct narrative inaccurate, possibly "playing it safe" (AUTHOR SPECULATION). With relative terms like "larger file size" and no distribution given, the grader was confused. Both are hints that domain priors and relative language break automated grading.

### 2.4 He & Martens (2026), Mermigkis et al. (WCCI 2026), PONTE (2026): the 2026 "verify-and-repair" wave
- (FACT / ABSTRACT) These papers treat table-faithfulness (rank, sign, value, absent features) as a solved *measurement* problem and move to *repair loops* (critic agents, verifier LLMs). (SYNTHESIS) Proposing "a new metric for SHAP-narrative faithfulness" in general ML is therefore **not novel in 2026**.

### 2.5 Setting (c) literature: a relevant finding for "domain-knowledge hallucination"
- (FACT) Mayne et al. 2026, Fig. 7: in self-explanations, **features that require domain expertise** (Radiation therapy RR=1.83, Education level RR=1.60) drive egregious unfaithfulness, and these are *not* the most important features. (SYNTHESIS) The pattern that domain-laden features attract unfaithful narration is documented for self-explanations, but not for narration of an external soccer model.
- (FACT) Feustel et al. 2025: experts judged LLM explanations *less* factually correct than templates while lay users judged them *more* correct. (SYNTHESIS) Evaluation needs domain-literate judges. For soccer that means a football-literate rater, i.e. the student themself, as a limited stand-in.

## 4. Verdict: what is FALSIFIED vs plausibly OPEN

### FALSIFIED (already done; do not claim as novel)
1. **"Evaluate whether LLM narratives of a tabular model's SHAP values are faithful in feature, sign, rank and value."** Done: Ichmoukhamedov et al. 2024 (RA/SA/VA with a validated extractor), He & Martens 2026, Explingo 2024 (accuracy/completeness graders), plus Mermigkis 2026 and PONTE 2026. (FACT)
2. **"LLMs override attributions that contradict their priors."** Demonstrated with manipulated SHAP tables (sign self-correction up to ~30%), including on a **FIFA Man of the Match** dataset (Ichmoukhamedov 2024). "Injected assumptions" were named and measured, though inconclusively. (FACT) So "domain-knowledge hallucination" *as a concept* is not new.
3. **"LLM verbalization of a soccer xG model, with an automated accuracy check."** Done in Rahimian et al. 2025 (journal-published), with code. (FACT)
4. **"Human evaluation of the faithfulness of soccer wordalisations."** Partly done for *scouting stats* (Caut et al., n=26 raters), not for xG model explanations. (FACT)
5. **"Narratives increase trust or reliance without improving decisions."** Done: Marusich 2026, Lukassen 2026. (FACT)

### Plausibly OPEN (no evidence found; see queries below)
- **O1. Faithfulness under natural prior-model conflict in an action-level soccer model.** #4 manufactured its conflicts. In a real xG model, counter-intuitive but *correct* contributions arise naturally: mean-centred binaries ("right foot increased xG"), collinear pressure features, per-competition coefficient flips. Nobody has measured how often LLM narratives misstate these relative to intuitive ones. **Measurement: stratify SA/RA by whether a contribution agrees with a football-prior direction.** (SYNTHESIS; plausibly open)
- **O2. "Absent-feature" or "non-contributing-feature" hallucination.** Rahimian scored only 2 features, and #4 *drops* extracted features that are not in the table. The rate at which narratives credit features the model lacks (e.g. GK positioning when it is ablated, "composure", "first-time finish") or features under the 0.1 threshold (e.g. "defensive pressure" when it is not contributing) seems unmeasured in soccer. **This is the cleanest gap.** It can be tested by *ablation*: retrain the xG model without feature group G, keep G's descriptive words in the prompt, and count narratives that still attribute influence to G. (SYNTHESIS; plausibly open)
- **O3. The pipeline design factor.** Wordalisation's pre-LLM "synthesized text" versus handing raw contributions/SHAP to the LLM (Explingo/#4 style). Which one reduces O1/O2 errors, and does the few-shot "how to answer" step (engagement) increase them? Explingo found few-shot hurts accuracy in general ML; this has not been tested in soccer. (SYNTHESIS)
- **O4. Non-linear models.** Rahimian explicitly leaves "wordalising SHAP of an XGBoost xG" as open. Where TreeSHAP interactions make the explanation less intuitive, faithfulness may drop. (FACT that they state it is open; SYNTHESIS that it is untested)
- **O5. The Vis4ML angle.** A linked view that maps each extracted narrative claim to the matching contribution bar or pitch element (claim-level provenance, flagged mismatches) to help a user spot unfaithful sentences. I found no soccer instance. The general VIS literature (e.g. chart-caption hallucination) was *not* searched exhaustively, so treat this as unverified. (SPECULATION, needs a slice-specific search)
- **O6. A small local open-weight narrator/extractor in this domain** (gpt-oss-20b). The evidence that small models are weak is mixed: Explingo's Mistral-7B was poor; AlMarri used small models in setting (c). On its own this is a weak novelty; it works as a secondary factor. (SYNTHESIS)

## 5. Feasibility with local gpt-oss-20b via Ollama (no paid API)
- (FACT) Rahimian's pipeline is reproducible from public materials: StatsBomb open data plus the repo, which includes model parameter files and `Case*.csv` outputs. The xG and contribution parts need no LLM.
- (FACT) The code calls Azure OpenAI (`openai==0.28`, `api_type="azure"`) or Gemini, and uses embeddings for Q/A retrieval. (SPECULATION, moderate confidence) Porting takes about 2-4 hours: point the OpenAI client at Ollama's OpenAI-compatible endpoint (`http://localhost:11434/v1`), which requires upgrading or changing the client, and use a local embedding model (e.g. `nomic-embed-text`).
- (AUTHOR CLAIM, OpenAI model card; not re-verified here) gpt-oss-20b is a mixture-of-experts reasoning model, about 21B total / 3.6B active parameters, that runs in about 16 GB of memory and has adjustable reasoning effort. (SPECULATION) Expect roughly 5-30 s per narrative on a laptop, depending on hardware and reasoning effort. At 300 shots x 4 conditions x 2 seeds, that is about 2,400 generations plus 2,400 extractions, or about 10-35 GPU-hours of unattended runs. Feasible, but cap n early.
- **Judge/extractor risk.** Using gpt-oss-20b both to generate and to extract is self-grading, the flaw in Rahimian. Mitigations (SYNTHESIS):
  - Make the extraction step JSON-schema constrained (Ollama `format`) and validate it the way #4 did: a manipulated-table true-negative test plus a manual check of about 50 narratives by the student.
  - Where possible, use **deterministic checks**: string or lexicon matching of feature mentions and sign words against a football-term dictionary. This is especially suitable for O2 (absent features).
  - If possible, use a second, different local model (e.g. a Qwen or Llama 8B) as a cross-check extractor.
- Explingo's Mistral-7B result (accuracy 0.98/4) suggests small models may fail at *parsing* the tables. Wordalisation's pre-verbalized synthesized text may be *more* robust for small models than raw SHAP tables. That is a testable, course-sized sub-question (SPECULATION).
- #4's perplexity metric needs token log-probs. I could not confirm whether Ollama exposes them for gpt-oss (unverified). If it matters, compute them with HF transformers on a small model.
- Frontend: reuse the repo's Streamlit app instead of building a custom UI. A linked "claim to contribution bar" view is small in Streamlit/Plotly (SPECULATION: about 6-10 h).
