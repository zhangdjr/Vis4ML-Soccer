# 05 - Soccer data and tooling availability (verified 2026-09-27)

Scope: public soccer data and open-source tooling for a solo, ~40-hour Visualization-for-ML project (xG / pass-success / action-value models plus explanations, or possession/tactical embeddings). Hardware: MacBook M1 Pro 32 GB plus a SLURM HPC cluster.

**How I checked things.** "API" means I queried GitHub (`gh api repos/...`) or the PyPI JSON API for the last push date, license and version. "Fetched" means I downloaded the actual index file with curl and counted records myself. "Range-GET" means I requested only the first bytes of a large file (HTTP 206), which proves the download link works without pulling the whole file. "Web" means the number comes from the provider page or a paper and I did not re-check it against the data. Anything marked **unverified** is exactly that.

## 2. Established baselines a student can actually reproduce

A **baseline** here is a published model plus evaluation protocol you can re-run to check your own numbers against.

1. **The StatsBomb xG field.** Every shot carries `statsbomb_xg` (the vendor's own model), so you get a free reference model. You can report AUC, Brier score and calibration for your xG model against it on the same shots. This is the cheapest credible "baseline" there is. Brier score is the mean squared error of predicted probabilities, so lower is better.
2. **socceraction VAEP and xG notebooks on StatsBomb.** VAEP (Valuing Actions by Estimating Probabilities) scores each on-ball action by how much it changes the chance of scoring or conceding soon after. The pipeline is fully reproducible, but the shipped metrics are in-sample. Re-run it with a proper split, for example Euro 2020 + WC 2022 for training and Euro 2024 for testing.
3. **un-xPass on Euro 2020 360.** Pass success, selection and value models (SoccerMap CNN, XGBoost and simple baselines), with configs for train/test splits. This is the closest thing to a published pass-success benchmark on open 360 data. The exact reported AUC/Brier numbers are **unverified by me**; read them from the KDD 2023 paper.
4. **soccer_xg on Wyscout open data.** Four pretrained open-play xG pipelines, plus the KU Leuven blog series on how xG depends on features and data quality. The numbers are in the blog posts (I did not re-read them, so **unverified**).
5. **OpenSTARLab Event benchmark** (next-event prediction). On Wyscout, LEM_3 reaches action accuracy 0.67, F1 0.20 and time MAE 2.69 s (from the Event README). The StatsBomb results use non-open La Liga 2023/24 data, so only the Wyscout half is reproducible.
6. **VAEP original results** (Decroos et al., KDD 2019) used Wyscout-like and other data. The metrics are **unverified** here.
7. **No standard benchmark exists for tracking-based pass success on open data.** SkillCorner's dynamic-event EPV and pressure columns can act as a vendor "teacher" signal. On IDSSE, researchers typically do case studies rather than leaderboards.

## 3. Recommended data stack for a 40-hour project

**Primary: StatsBomb Open Data with 360 (event data plus freeze-frames), loaded through kloppy or statsbombpy, modeled with socceraction or un-xPass, rendered with mplsoccer.**

Why this and not tracking data:
- **It has the richest features per hour of effort.** Shot freeze-frames exist for all 3,961 matches, 360 frames exist for 426 matches, and none of it needs synchronization work. You can go from `pip install` to a shot table in under an hour.
- **Defender positions become interpretable features.** From the shot freeze-frame (with player identities) or the 360 frame (anonymous) you can compute: number of defenders in the shot triangle (the triangle from the ball to both goalposts), distance to the nearest defender, goalkeeper position and angle off the goal line, and a pressure count within 2-5 m. These features are exactly what explanation methods such as SHAP (per-feature contributions to one prediction) or partial dependence plots (average prediction as one feature varies) make intuitive. They are also directly drawable on a pitch, which suits a Vis4ML story of "model says X because of these defenders".
- **A built-in reference model** (`statsbomb_xg`) gives you a comparison baseline and a disagreement analysis for free: "where does my model disagree with StatsBomb, and why?"
- **Clean train/test splits by tournament.** WC 2022 (64), Euro 2020 (51), Euro 2024 (51), WWC 2023 (64), WEuro 2022/2025 (31+31) all have *full* 360 coverage and multi-team samples. Split by tournament so no match leaks across the split. Avoid the single-club 360 seasons for evaluation because of selection bias (Barcelona / PSG / Leverkusen / Inter Miami).
- **Pass success comes almost free.** Passes carry an outcome label (a missing `pass.outcome` means completed), and un-xPass already gives you a feature pipeline built on 360 data.
- **Compute is trivial.** XGBoost on about 10^5 passes or about 10^4 shots trains in seconds on the M1. The HPC is only needed if you try a SoccerMap CNN or a GNN.

**Secondary (optional, only if the project is about possession or tactical embeddings): SkillCorner Open Data (20 matches, MIT, 10 Hz) and/or IDSSE (7 matches, CC BY, 25 Hz optical), loaded via kloppy, with unravelsports for graphs.**
- SkillCorner has the permissive license, player ids, phases-of-play labels (useful as weak labels to color or validate embeddings) and vendor EPV/pressure columns to explain against. It is 20 matches from one league, so treat it as an exploratory-embedding dataset, not a generalizable model.
- IDSSE is the best "ground-truth" tracking, but only 7 games and multi-GB XML. Use it for case-study visualizations.
- The PFF WC 2022 release would pair perfectly with StatsBomb WC 2022 360 (same 64 matches). It requires a registration form with unverified terms, so treat it as a stretch goal and do not depend on it.

**Budget sketch (about 40 h):** 3 h environment setup (a Python 3.11 env for socceraction; kloppy and mplsoccer in the same env) → 5 h building shot and pass tables with 360 features → 6 h models (logistic regression plus XGBoost for xG and pass success, with calibration) → 4 h evaluation against `statsbomb_xg` → 16 h visual explanation interface (pitch view plus SHAP / counterfactual defender dragging) → 6 h write-up. Optionally, substitute 8 h of the interface time for a SkillCorner possession-embedding view.

**Avoid for this project:** GRF (archived, hard to build on M1, simulated distribution), SoccerNet / SportsMOT / TeamTrack / SoccerTrack v1 (computer-vision datasets, NDA or heavy video), Last Row (not research grade), Metrica (3 anonymized games, no license file; fine only as a demo).
